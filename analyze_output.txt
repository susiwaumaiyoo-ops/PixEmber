================================================================================
1. プロジェクト全体像
================================================================================

[概要]
pixiv_viewer/ は、Pixiv の「App-API（app-api.pixiv.net）」を直接呼び出す
非公式 Pixiv クライアント。Dart の http クライアントで OAuth（リフレッシュトークン）
による認証を行い、推奨/検索/ランキング/小説/うごイラ/ブックマーク等を取得・表示する。

[主要技術スタック]
- Flutter/Dutter (Dart)
- 永続化: sqflite（SQLite ファイル名 pixiv_viewer.db、バージョン 8）
- 認証: OAuth2 リフレッシュトークン（SharedPreferences キー PIXIV_REFRESH_TOKEN）
        ログインは PKCE（S256）の WebView フロー + リフレッシュトークン交換
- 画像: ネットワーク画像に Referer ヘッダ必須（CDN 403 回避）
- 埋め込み検索: ONNX Runtime（flutter_onnxruntime）+ Ruri v3-310m INT8 モデル
        ＋ SentencePiece トークナイザ（dart_sentencepiece_tokenizer）
- クラウド同期: Google Sign-In + googleapis/drive v3（appDataFolder の
        pixember_backup.json を backup/restore）
- ディープリンク: app_links パッケージ（pixiv.net の作品 URL をアプリ内で開く）
- うごイラ再生: archive（ZIP 展開）+ Timer によるフレーム再生

[アプリのエントリ]
- lib/main.dart → MyApp（runApp）。起動時に AppLinks を初期化し、
  初期リンク/ストリームリンクを _handleLink → _navigate で処理。
- lib/screens/home_screen_state.dart → PixivViewerHome（ボトムナビ:
  イラスト/小説/フィーリング発掘）。各種取得・ログイン・Drive 同期の実体を保持。

3. 主要データフロー
================================================================================

[認証フロー]
1. 起動時 _checkLoginOnStart（home_screen_state.dart）でリフレッシュトークン有無を確認。
2. 未ログイン → showPKCELoginDialog → _showWebViewLogin（webview_flutter で
   https://app-api.pixiv.net/web/v1/login を開く）。
3. pixiv://auth リダイレクトを _handleAuthRedirect で捕捉 →
   _exchangeCodeForToken（oauth.secure.pixiv.net/auth/token、grant_type=authorization_code）
   → リフレッシュトークンを setRefreshToken() で SharedPreferences に保存。
4. 以降、API 呼び出し時に getAccessToken(refreshToken) で都度アクセストークン取得。

[一覧取得・表示フロー（イラスト/小説共通）]
home_screen_state.fetchData() / fetchNextPage()
  → PixivApiService.getRecommend/searchIllust/getRanking/... 等
  → _loadMuteFilter() で DB ミュートを読み込み
  → filterIllustsIsolated / filterNovelsIsolated（Isolate.run でメイン直列フィルタ回避）
  → 結果を state.illusts / state.novels に保持 → home_ui_components がグリッド描画

[小説の埋め込み生成フロー（バックグラウンド）]
fetchData 後 → _generateEmbeddingsInBackground(novels)
  → 最大5件ずつ _runBackgroundEmbeddingGeneration
  → EmbeddingService().encodeDocument(buildNovelDocumentText(novel, bodyText))
  → DatabaseService().saveNovelEmbedding(...) / saveNovel(...)

[フィーリング発掘（埋め込み検索）フロー]
feeling_discovery_screen 入力 → EmbeddingService().encodeQuery(...)
  → database_search.searchNovelsByEmbedding(db, queryEmbedding)
  → コサイン類似度で上位を抽出（model_id/version 不一致はスキップ）
  → 結果不足時は searchNovelsByKeywordFallback（タイトル/説明 LIKE）

[小説閲覧フロー]
novel_detail_screen → タップで NovelReaderScreen(novel)
  → novel_reader_data._initSequence → _fetchNovelText（DB 優先 / なければ API）
  → 本文をページ分割して表示、読書設定を SharedPreferences に保存
  → しおり（自動）を DatabaseService に保存

[Google Drive 同期フロー]
home_sync_handler / home_ui_components の Drawer
  → GoogleDriveService.signIn / backupJSON / restoreJSON
  → backupJSON = DatabaseService().exportAllData() をアップロード
  → restoreJSON = ダウンロード → DatabaseService().importAllData()（実体は
     database_search.importAllData 経由で novels/novel_text/novel_embeddings をマージ）

4. DB・永続化の整理
================================================================================

[DB 基本情報]
- ファイル: pixiv_viewer.db（sqflite）
- バージョン: 8（_onUpgrade で v1→v8 までマイグレーション）
- 操作の中心: lib/services/database_service.dart（DatabaseService シングルトン）

[テーブル一覧と責務]
- history            : 閲覧履歴（id,title,type,work_id,author_name,url,metadata,created_at）
                      使用: 各詳細画面の _recordHistory / history_screen 表示。
- novels             : 小説メタ（id,title,description,author_id,series_id,series_order,
                      text,text_length,tags,tags_json,x_restrict,novel_ai_type,
                      created_at,updated_at,author_name,cover_url,page_count,
                      total_bookmarks,create_date,total_view,meta_json）
                      使用: 検索結果保持・埋め込み検索の結合・フォルダ等。
- novel_text         : 小説本文（work_id,title,author_name,pages_json,text,updated_at）
                      使用: NovelReaderScreen の本文取得・保存。
- novel_embeddings   : 小説埋め込みベクトル（work_id,embedding,model_id,model_version,updated_at）
                      embedding は JSON 文字列（Float32List を jsonEncode）。
                      使用: database_search.searchNovelsByEmbedding。
- downloaded_illust  : ダウンロード済みイラスト（illust_id,local_path,thumbnail_path,download_date）
                      使用: DownloadService（推測）。
- mutes              : ミュート（id,mute_type,value,label）
                      mute_type = tag | user | ai（ai は '0'/'1'/'2' で AI 扱いを制御）
                      使用: PixivApiService._loadMuteFilter → フィルタ適用。
- folders            : お気に入りフォルダ（id,name,created_at）
                      使用: folder_list_screen / folder_selection_bottom_sheet。
- folder_items       : フォルダ内作品（id,folder_id,work_id,title,author_name,preview_url,type,added_at）
                      使用: folder_items_screen。
- subscribed_tags    : 購読タグ（id,tag,type,created_at）【v3 で追加】
                      使用: addSubscribedTag（novel_detail_screen から呼ばれる）で書き込みのみ。
                      実際の「バックグラウンド同期」は subscriptions_screen（旧サーバー）経由で、
                      本テーブルはローカル保存の受け皿としてのみ機能。

[マイグレーション要点]
- v2: mutes.label / subscribed_tags 準備（実際は v3 で subscribed_tags 追加）
- v3: novel_text.title/author_name、subscribed_tags 追加
- v4: history.author_name
- v5: novels メタ列拡張
- v6: novel_embeddings クリア（次元バグ修正）
- v7: novel_embeddings に model_id/model_version 追加（→ モデル不一致スキップの根拠）
- v8: novels.total_view / meta_json 追加

[インデックス]

6. 旧バックエンド依存が残る箇所
================================================================================

[結論]
旧バックエンド（Python サーバー: ルートの main.py / app.py 群）への依存は、
「subscriptions_screen.dart」にのみ残存している。ただし本画面は
**アプリ内のどこからも push/生成されていない（到達不能デッドコード）** と判断。

[subscriptions_screen.dart の依存内容]
- コンストラクタで `final String host` と `onTagSelected` コールバックを受ける。
- 以下の HTTP エンドポイントを直接呼び出す（http パッケージ）:
    GET  ${host}/api/subscriptions
    POST ${host}/api/subscriptions/remove
    POST ${host}/api/subscriptions/sync
    POST ${host}/api/subscriptions/sync?tag_id=<id>
    GET  ${host}/api/subscriptions/sync/status  （1秒ごとポーリング: is_running/total/progress）
- これは「サーバー側で24時間バックグラウンドタグ同期を行う」バックエンドを前提としている。
  → クライアント単体では動作不可能な設計がそのまま残っている。

[関連する残骸・未接続箇所]
- database_service.addSubscribedTag は定義されており、
  novel_detail_screen._showSubscriptionDialog（:108）から実際に呼ばれ、
  subscribed_tags テーブルへローカル保存されている（部分的に動作）。
- しかし「登録したタグをサーバーへ同期する」導線は subscriptions_screen のみで、
  同画面が到達不能なため、subscribed_tags は「書き込みだけされ、同期に使われない」状態。
- illust_detail_handler.showSubscriptionDialog（:108）は
  `// TODO: サブスクリプション登録実装` のまま未実装（登録処理なし）。
- home_ui_components.buildSyncProgressHUD / isSyncing は
  「Google ドライブ同期中...」用であり、subscriptions（旧サーバー）とは無関係。

[旧バックエンド依存まとめ]
- 残存ファイル: subscriptions_screen.dart（到達不能・デッドコード）
- 影響: 実行時には到達しないため現在のアプリ挙動には影響なし。
  ただし「購読タグのバックグラウンド同期」機能自体が未完成/未接続。
- 推奨（実装フェーズ用・未実施）:
  subscriptions_screen を廃止するか、host をなくして
  ローカル（subscribed_tags のみ）または Google Drive ベースの同期に再設計する。

8. 低リスク機能案（実装しやすく影響範囲の小さい候補）

以下は既存アーキテクチャに乗るだけで実現でき、既存 API/DB/Widget を大きく壊さない
候補（あくまで提案。未実装）。
